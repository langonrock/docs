## Installing a package

```bash
npm install <package>          # runtime dependency
npm install -D <package>       # build-time only
```

Commit `package-lock.json` with the change. Use `npm ci` in CI and in deployment so the lockfile is
respected exactly.

Runtime versus dev matters here: anything imported by a component, a route, or an MDX file is a
runtime dependency, even if it only runs at build time — the static build still executes that code.
Only tooling that never appears in an import chain (linters, type packages, build plugins) belongs
in `devDependencies`.

## Importing in a component

Normal ES imports. The `@/*` alias from `tsconfig.json` points at `src/`:

```tsx title="src/components/chart.tsx"
import { format } from 'date-fns';
import { cn } from '@/lib/cn';

export function Chart({ className }: { className?: string }) {
  return <div className={cn('rounded-lg border', className)}>{format(new Date(), 'PPP')}</div>;
}
```

Prefer `@/...` over long relative chains. Both work; the alias survives file moves.

## Importing in MDX

MDX files are compiled as modules, so they can import too:

```mdx title="content/docs/example.mdx"
---
title: Example
---

import { Chart } from '@/components/chart';

<Chart />
```

To make a component available in every page without an import, register it in
`src/components/mdx.tsx` instead — see [Components](/docs/writing/components).

<Callout type="warn">
  Importing a package directly in an MDX file pulls it into that page's bundle. For something used
  on one page that is the right trade; for something used on twenty, register it once and let the
  shared chunk be shared.
</Callout>

## Server and client

Every component here is a Server Component by default. Server Components run only at build time —
their code never reaches the browser, and neither does the code of anything they import. That is why
a heavy Markdown or date library used purely for rendering costs nothing at runtime.

A component needs `'use client'` at the top of its own file when it uses hooks, state, effects,
event handlers, or browser APIs:

```tsx title="src/components/counter.tsx"
'use client';

import { useState } from 'react';

export function Counter() {
  const [n, setN] = useState(0);
  return <button onClick={() => setN(n + 1)}>{n}</button>;
}
```

The directive goes in the component file, never in the MDX. Everything a client component imports is
shipped to the browser with it, so the boundary is also the bundle boundary — push `'use client'` as
far down the tree as it will go.

<Callout type="error">
  Never import a package that reads secrets, touches the filesystem, or talks to a database from a
  client component. Whatever it imports is downloadable. See
  [Environment & Secrets](/docs/operations/environment).
</Callout>

## Loading something heavy

For a widget that is large and not needed immediately, defer it:

```tsx
import dynamic from 'next/dynamic';

const Diagram = dynamic(() => import('@/components/diagram'), {
  loading: () => <p>Loading…</p>,
});
```

`ssr: false` is available for components that genuinely cannot render on the server — but it means
the content is invisible to crawlers and to the search index, so avoid it for anything that is part
of the documentation itself.

Fumadocs already does this for the search dialog, which is why the search bundle only loads when the
dialog opens.

## Bundle configuration

Three options in `next.config.mjs` cover most cases. Add them to the `config` object — `withMDX()`
merges it.

```js title="next.config.mjs"
const config = {
  reactStrictMode: true,
  transpilePackages: ['some-untranspiled-package'],
  serverExternalPackages: ['heavy-node-only-package'],
  experimental: {
    optimizePackageImports: ['some-large-icon-library'],
  },
};
```

| Option | Use when |
| --- | --- |
| `transpilePackages` | A dependency ships untranspiled ESM or TypeScript and fails to parse |
| `serverExternalPackages` | A server-only package should stay external instead of being bundled — native modules, large Node libraries |
| `experimental.optimizePackageImports` | A barrel-export package (icon sets, component kits) pulls in far more than you use |

`lucide-react` is already handled internally by Next.js, so it does not need the last one.

## Measuring the bundle

```bash
npm install -D @next/bundle-analyzer
```

```js title="next.config.mjs"
import { createMDX } from 'fumadocs-mdx/next';
import withBundleAnalyzer from '@next/bundle-analyzer';

const withMDX = createMDX();
const withAnalyzer = withBundleAnalyzer({ enabled: process.env.ANALYZE === 'true' });

export default withAnalyzer(withMDX({ reactStrictMode: true }));
```

```bash
ANALYZE=true npm run build
```

Wrapping order matters: `createMDX()` must be applied first so the analyzer sees the final config.

## Static assets

There is no `public/` directory yet. Create one at the repository root and reference its contents
from the site root:

```
public/logo.svg      →  /logo.svg
public/diagram.png   →  /diagram.png
```

```mdx
![Architecture](/diagram.png)
```

Files in `public/` are served verbatim, without processing or hashing — so use content-addressed
names or accept that caches may hold an old version. For images that should be optimized, import
them and use `next/image` in a component rather than referencing them as paths.

## A caveat about `pageExtensions`

`createMDX()` sets `pageExtensions` to `['mdx', 'md', 'jsx', 'js', 'tsx', 'ts']`. Inside `src/app/`,
a file named `page.ts` or `route.ts` is a route — that is expected. What is easy to forget is that
adding `.md` and `.mdx` to that list means a stray `page.mdx` in the app directory would also become
a route. Keep documentation content in `content/docs/`, where the loader owns it.

## Auditing what you have

```bash
npm ls --depth=0      # direct dependencies
npm outdated          # available updates
npm audit             # known vulnerabilities
```

Note that `fumadocs-ui` appears as an alias to `@fumadocs/base-ui`, and that `@fumadocs/base-ui`
pins `next` to `16.x` and `fumadocs-core` to `16.14.0` exactly. Upgrading one of those three means
upgrading them together.
