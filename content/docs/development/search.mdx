Search works with no configuration. Press <kbd>Cmd</kbd>/<kbd>Ctrl</kbd> + <kbd>K</kbd> on any page.
Both halves of it are three lines of code.

## The server

```ts title="src/app/api/search/route.ts"
import { source } from '@/lib/source';
import { createFromSource } from 'fumadocs-core/search/server';

export const { GET } = createFromSource(source);
```

`createFromSource` walks `source.getPages()`, builds one index record per page — including its
breadcrumbs and its locale — and hands them to the search engine. Index records are built on first
request and cached, keyed by the loader instance.

<Callout type="warn" title="This is zbsearch, not Orama">
  `fumadocs-core` 16 uses [`zbsearch`](https://www.npmjs.com/package/zbsearch) as its server engine.
  Nearly every Fumadocs guide, blog post, and Stack Overflow answer written before that says Orama,
  and their configuration snippets do not apply. Orama survives here only as an optional static
  client, which this project does not use.
</Callout>

By default `createFromSource` builds the **advanced** index: section-level rather than page-level,
so a hit points at the specific heading rather than the top of the page. The schema holds `content`,
`page_id`, `type`, `breadcrumbs`, `tags`, `url`, `locale`, and an `embeddings` vector.

The tokenizer language defaults to `multilingual`, which handles every language without
configuration. Older `language: 'english'` style options and `localeMap` still exist but are marked
deprecated.

## The client

Nothing in this repository wires up the client. `RootProvider` in `src/app/layout.tsx` mounts a
`SearchProvider`, which lazily loads the default dialog, which calls `/api/search`. The endpoint
matches the route above by convention, which is why zero configuration is needed.

To customize, pass `search` options to `RootProvider`:

```tsx title="src/app/layout.tsx"
<RootProvider
  search={{
    links: [
      ['Home', '/'],
      ['Documentation', '/docs'],
    ],
  }}
>
  {children}
</RootProvider>
```

| Option | Effect |
| --- | --- |
| `enabled` | `false` removes search entirely — no dialog, no hotkey, no trigger |
| `links` | Shortcuts shown when the query is empty |
| `hotKey` | Replaces <kbd>Cmd</kbd>/<kbd>Ctrl</kbd> + <kbd>K</kbd> |
| `SearchDialog` | Swaps the dialog component, for a different provider |
| `options` | Extra props forwarded to the dialog |

Disabling search means the `/api/search` route is dead weight — delete it too.

## Querying the API directly

```bash
curl -s 'http://localhost:3000/api/search?query=frontmatter' | head -40
```

| Parameter | Meaning |
| --- | --- |
| `query` | The search text |
| `locale` | Restrict to a locale |
| `tag` | Filter by tag |
| `limit` | Maximum results |
| `mode` | `full` (default) or `vector` |

`mode=vector` requires embeddings stored in the index. `buildIndex` does not generate them, so
vector mode returns nothing useful until you supply them yourself.

## Customizing what gets indexed

Pass `buildIndex` to control the record for each page:

```ts title="src/app/api/search/route.ts"
export const { GET } = createFromSource(source, {
  buildIndex(page) {
    return {
      title: page.data.title,
      description: page.data.description,
      url: page.url,
      id: page.url,
      structuredData: page.data.structuredData,
      tag: page.data.category,
    };
  },
});
```

A `tag` on each record is what makes the `tag` query parameter useful — for splitting results by
product or version, for example.

## Alternative providers

`fumadocs-core` ships adapters for hosted search, and `fumadocs-ui` ships matching dialogs:

| Provider | Server | Dialog |
| --- | --- | --- |
| Algolia | `fumadocs-core/search/algolia` | `fumadocs-ui/components/dialog/search-algolia` |
| Orama Cloud | `fumadocs-core/search/orama-cloud` | `fumadocs-ui/components/dialog/search-orama` |
| Mixedbread | `fumadocs-core/search/mixedbread` | — |
| Static (client-side) | `staticGET` on the API | `fumadocs-core/search/client/orama-static` |

The static option is the interesting one for a fully static deployment: `createFromSource` returns a
`staticGET` handler that exports the whole index as a file, and the client searches it in the
browser. That removes the only route in this project that has to run per request — at the cost of
downloading the index. It becomes a bad trade as the site grows.

## Verifying the index

After adding pages, search for a phrase that only appears in the new content. If it returns nothing:

- the page is missing required frontmatter and never entered the source;
- the dev server has not picked up the file yet — check the terminal;
- a custom `buildIndex` is dropping the field you searched.
