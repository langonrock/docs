## Scripts

| Script | Command | When |
| --- | --- | --- |
| `npm run dev` | `next dev` | Local development. Watches `content/` and hot-reloads. |
| `npm run build` | `next build` | Production build. Fails on any MDX or type error. |
| `npm start` | `next start` | Serves the output of `npm run build`. |
| `npm run types:check` | `next typegen && tsc --noEmit` | Type checking. |
| `npm run lint` | `eslint` | Linting. |

Next.js 16 uses Turbopack by default for both `dev` and `build`, which is why no `--turbopack` flag
appears in the scripts. `createMDX()` registers its loaders for both Turbopack and Webpack, so
opting back into Webpack with `--webpack` still works.

## Why `types:check` is two commands

Next.js 16 generates the types for page and layout props rather than exporting them. Files across
this project use them:

```tsx title="src/app/docs/[[...slug]]/page.tsx"
export default async function Page(props: PageProps<'/docs/[[...slug]]'>) {
```

`PageProps`, `LayoutProps`, and `RouteContext` are globals written into `.next/types` by
`next typegen`, and `tsconfig.json` includes that directory. Running `tsc --noEmit` on a clean
checkout fails because those types do not exist yet. Always use `npm run types:check`.

## Linting

`eslint.config.mjs` is a flat config that spreads `eslint-config-next/core-web-vitals` and ignores
build artifacts:

```js title="eslint.config.mjs"
globalIgnores(['.next/**', 'out/**', 'build/**', 'next-env.d.ts', '.source/**'])
```

`.source/**` is ignored because it is generated — never edit or lint it.

## Before you push

```bash
npm run lint
npm run types:check
npm run build
```

The build is the real gate. MDX errors, missing required frontmatter, and broken component imports
all surface there and nowhere earlier.

## Commits

The repository follows [Conventional Commits](https://www.conventionalcommits.org/):

```
type(scope): subject
```

Types in use: `feat`, `fix`, `docs`, `refactor`, `chore`, `test`, `style`, `perf`, `build`, `ci`.
Subject in the imperative mood, lowercase, no trailing period.

```bash
git commit -m "docs(writing): add frontmatter reference"
git commit -m "fix(search): correct the API route path"
```

Documentation-only changes use `docs`. Changes to `content/docs/**` are almost always `docs`.

<Callout type="warn">
  Do not add `Co-Authored-By:` trailers or any other AI attribution to commits. This is a project
  rule recorded in `CLAUDE.md`.
</Callout>

## About `CLAUDE.md`

`CLAUDE.md` at the repository root is a set of behavioral guidelines for AI coding assistants —
think before coding, keep changes surgical, avoid speculative abstraction, write everything in
English, treat specs as contracts. It is not project documentation and it describes nothing about
langondocs specifically. If you are looking for how the project works, you are in the right place
already.
