## Current state

The project uses **no environment variables**. There is no `.env` file, and nothing outside Next.js
internals reads `process.env`. Everything configurable lives as a plain constant in
`src/lib/shared.ts` — see [Configuration](/docs/operations/configuration).

That is a reasonable place to be for a static documentation site. This page covers what to do when
that stops being true.

## Environment variables

Next.js loads these files automatically, in order of precedence:

| File | Loaded in | Commit it? |
| --- | --- | --- |
| `.env.local` | Every environment except test | **No** — gitignored |
| `.env.development` | `next dev` | Yes |
| `.env.production` | `next build` and `next start` | Yes |
| `.env` | Always, lowest precedence | Yes |

`.gitignore` already covers `.env*.local`. Nothing else is ignored, so a secret written to `.env` or
`.env.production` will be committed. Secrets belong in `.env.local` locally and in the host's
environment settings in production.

### Server versus browser

```bash title=".env.local"
GITHUB_TOKEN=ghp_xxxxxxxxxxxx           # server only
NEXT_PUBLIC_SITE_URL=https://docs.example.com   # inlined into the browser bundle
```

<Callout type="error" title="NEXT_PUBLIC_ means public">
  A `NEXT_PUBLIC_` variable is substituted into the JavaScript at build time. It is visible to
  anyone who opens devtools, and it is baked into the deployed artifact — rotating it means
  rebuilding. Never prefix a secret.
</Callout>

Variables without the prefix are readable only in Server Components, route handlers, and
`proxy.ts`. Reading one from a `'use client'` component yields `undefined` — which fails quietly
rather than loudly, so it is worth asserting:

```ts
const token = process.env.GITHUB_TOKEN;
if (!token) throw new Error('GITHUB_TOKEN is not set');
```

### Build time versus run time

This site is almost entirely static, so most variables are read **during the build**, not on each
request. Changing one in the host's dashboard has no effect until you redeploy. Only `/api/search`
and `proxy.ts` read the environment per request.

## API tokens

### GitHub

The `GithubInfo` component fetches star and fork counts from the GitHub API. Unauthenticated
requests are rate-limited to 60 per hour per IP, which a build can exhaust:

```tsx title="src/components/repo-stats.tsx"
import { GithubInfo } from 'fumadocs-ui/components/github-info';
import { gitConfig } from '@/lib/shared';

export function RepoStats() {
  return (
    <GithubInfo
      owner={gitConfig.user}
      repo={gitConfig.repo}
      token={process.env.GITHUB_TOKEN}
    />
  );
}
```

The component is a Server Component, so the token stays server-side. A read-only token with no
scopes is enough for public repository metadata.

<Callout type="warn">
  `gitConfig` still points at `fuma-nama/fumadocs`, so this component would report the wrong
  repository's stars until that is corrected.
</Callout>

### Hosted search

If you move off the built-in search to Algolia, Orama Cloud, or Mixedbread
([Search](/docs/development/search)), each needs credentials. The pattern is always the same: the
write or admin key stays server-side and is used by an indexing script; only the search-only key is
exposed to the browser.

```bash title=".env.local"
ALGOLIA_ADMIN_KEY=...                      # server only, indexing
NEXT_PUBLIC_ALGOLIA_SEARCH_KEY=...         # browser, search-only
NEXT_PUBLIC_ALGOLIA_APP_ID=...
```

Getting these two backwards hands out write access to your index.

### Typing them

`process.env` values are `string | undefined`. To get them typed, declare them once:

```ts title="src/env.d.ts"
declare namespace NodeJS {
  interface ProcessEnv {
    GITHUB_TOKEN?: string;
    NEXT_PUBLIC_SITE_URL?: string;
  }
}
```

## HTTPS in development

Needed when testing OAuth callbacks, webhooks, secure cookies, or any browser API restricted to
secure contexts.

```bash
npx next dev --experimental-https
```

Next.js generates a locally trusted certificate with [`mkcert`](https://github.com/FiloSottile/mkcert)
and serves on `https://localhost:3000`. To use your own certificate:

```bash
npx next dev --experimental-https \
  --experimental-https-key ./certificates/localhost-key.pem \
  --experimental-https-cert ./certificates/localhost.pem
```

`--experimental-https-ca` supplies a custom certificate authority. This is a development convenience
only — the generated certificate is not for production.

To make it the default, change the script:

```json title="package.json"
"dev": "next dev --experimental-https"
```

## TLS in production

Next.js does not terminate TLS itself. Something in front of it does:

| Host | TLS handled by |
| --- | --- |
| Vercel | Automatic, including certificate renewal |
| Node behind nginx or Caddy | The reverse proxy |
| Container platform | The ingress or load balancer |

For a self-hosted setup, `npm start` listens on plain HTTP and the proxy terminates TLS:

```nginx
server {
  listen 443 ssl;
  server_name docs.example.com;

  ssl_certificate     /etc/letsencrypt/live/docs.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/docs.example.com/privkey.pem;

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
  }
}
```

`X-Forwarded-Proto` matters: without it, code that builds absolute URLs from the request sees
`http`, and redirects can drop users out of TLS.

Caddy does the same with automatic certificates:

```text title="Caddyfile"
docs.example.com {
  reverse_proxy 127.0.0.1:3000
}
```

## Absolute URLs

Set `metadataBase` once the domain is known. Without it the build warns and OG image URLs stay
relative, which social platforms will not fetch:

```tsx title="src/app/layout.tsx"
export const metadata: Metadata = {
  metadataBase: new URL(process.env.NEXT_PUBLIC_SITE_URL ?? 'http://localhost:3000'),
};
```

## Serving from a subpath

To host the docs at `example.com/docs` rather than at a domain root:

```js title="next.config.mjs"
const config = {
  reactStrictMode: true,
  basePath: '/docs',
};
```

`basePath` is prepended to every route, asset, and link automatically. It stacks with `docsRoute`,
so `/docs` plus a `docsRoute` of `/docs` yields `/docs/docs` — set `docsRoute` to `/` or pick a
different `basePath`. Verify the search endpoint and the OG image URLs after changing it; both are
built from paths that now sit behind the prefix.

## Security headers

Nothing is configured. For a public site, headers belong in `next.config.mjs`:

```js title="next.config.mjs"
const config = {
  reactStrictMode: true,
  async headers() {
    return [
      {
        source: '/:path*',
        headers: [
          { key: 'X-Content-Type-Options', value: 'nosniff' },
          { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
          {
            key: 'Strict-Transport-Security',
            value: 'max-age=63072000; includeSubDomains; preload',
          },
        ],
      },
    ];
  },
};
```

Add HSTS only once TLS is confirmed working — a long `max-age` on a misconfigured domain locks
browsers out of it for the duration.

A Content-Security-Policy is worth adding too, but Next.js injects inline scripts for hydration, so
it needs a nonce. Start from the
[Next.js CSP guide](https://nextjs.org/docs/app/guides/content-security-policy) rather than a
generic policy, and note that a nonce forces dynamic rendering — which would undo the static
generation this site relies on.
