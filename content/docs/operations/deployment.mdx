## Building

```bash
npm run build   # next build
npm start       # next start, serves the build
```

The build is the real test of the content. MDX syntax errors, missing required frontmatter, unknown
components, and broken imports all fail here and nowhere earlier.

## What is static

Almost everything. Every route that serves content declares `revalidate = false` or supplies
`generateStaticParams()`:

| Route | Rendering |
| --- | --- |
| `/` | Static |
| `/docs/*` | Static, one file per page |
| `/llms.txt`, `/llms-full.txt` | Static |
| `/llms.mdx/docs/*/content.md` | Static |
| `/og/docs/*/image.png` | Static |
| `/api/search` | **Dynamic** |

Search is the only route that must run per request. `proxy.ts` also runs per request, but as
middleware rather than a route.

## Vercel

Zero configuration. Connect the repository; Vercel detects Next.js, runs `npm run build`, and
deploys. Middleware (`proxy.ts`), the search route, and the generated OG images all work as they do
locally.

## Self-hosting with Node

```bash
npm ci
npm run build
npm start
```

`npm start` serves on port 3000 by default; `PORT=8080 npm start` changes it. Put it behind a
reverse proxy for TLS. The `.next` directory and `node_modules` both need to be present at runtime —
this is not a self-contained bundle unless you configure `output: 'standalone'` in
`next.config.mjs`.

## Docker

Not set up in this repository. If you add it, `output: 'standalone'` in `next.config.mjs` produces a
minimal server bundle that avoids shipping all of `node_modules`.

## Static export

`next export` style output is possible but costs two features:

- **`proxy.ts` stops running.** Markdown content negotiation via the `Accept` header disappears. The
  `.md` suffix URLs stop working too, since they are rewrites rather than real files.
- **`/api/search` stops running.** You would switch to the static search index — see
  [Search](/docs/development/search).

The `/llms.*` routes and the OG images survive, since they are already static. Only choose this if
the hosting target genuinely cannot run Node.

## Pre-deploy checklist

<Callout type="warn">
  The first item is not optional. The scaffold placeholders are still in `src/lib/shared.ts`.
</Callout>

1. **Replace `appName` and `gitConfig`** in `src/lib/shared.ts`. Until then the navbar reads "My
   App", every OG image is labelled "My App", and every "Open in GitHub" link points at
   `fuma-nama/fumadocs`. See [Configuration](/docs/operations/configuration).
2. **Move `proxy.ts` to `src/proxy.ts`**, or accept that Markdown content negotiation does not work.
   Next.js looks for it beside the app directory, which is `src/` here. See
   [LLM & Markdown Routes](/docs/development/llm-routes).
3. **Replace the landing page.** `src/app/(home)/page.tsx` is still "Hello World".
4. **Set `metadataBase`** in `src/app/layout.tsx` — see below. Without it the build warns and OG
   image URLs stay relative, which social platforms will not fetch.
5. `npm run lint`
6. `npm run types:check`
7. `npm run build`
8. Click through the site from `npm start`, not just `npm run dev` — production and development
   differ in rendering and caching.
9. Check one OG image renders: `/og/docs/<any-page>/image.png`.
10. Check `curl -s <host>/llms.txt` lists the pages you expect.

## Adding site metadata

There is no root `metadata` export, so pages get their own titles but the site has no default title
template, no favicon declaration, and no default social image. Worth adding before launch:

```tsx title="src/app/layout.tsx"
import type { Metadata } from 'next';
import { appName } from '@/lib/shared';

export const metadata: Metadata = {
  title: {
    template: `%s | ${appName}`,
    default: appName,
  },
  description: 'Documentation for ...',
  metadataBase: new URL('https://your-domain.example'),
};
```

`metadataBase` matters specifically for OG images: without it, the relative image URLs produced by
`getPageImageUrl()` cannot be resolved to absolute URLs, and social platforms will not fetch them.
