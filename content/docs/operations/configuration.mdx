## Site constants

`src/lib/shared.ts` is the single source of truth for the site's identity and routes. Everything
else derives from it.

```ts title="src/lib/shared.ts"
export const appName = 'My App';
export const docsRoute = '/docs';
export const docsImageRoute = '/og/docs';
export const docsContentRoute = '/llms.mdx/docs';

// fill this with your actual GitHub info, for example:
export const gitConfig = {
  user: 'fuma-nama',
  repo: 'fumadocs',
  branch: 'main',
};
```

<Callout type="error" title="Two placeholders are still in place">
  `appName` and `gitConfig` are the values `create-fumadocs-app` shipped. Nothing breaks visibly,
  which is exactly why they are easy to miss — the site just carries the wrong name and links to
  somebody else's repository.
</Callout>

### `appName`

Currently `'My App'`. It appears in:

- the navbar title, via `baseOptions()` in `src/lib/layout.shared.tsx`;
- every generated OG image, as the `site` label.

### `gitConfig`

Currently `fuma-nama/fumadocs`. This repository is `langonrock/docs`. It builds two links:

| Link | Built in | Current result |
| --- | --- | --- |
| Navbar GitHub icon | `src/lib/layout.shared.tsx` | `github.com/fuma-nama/fumadocs` |
| "Open in GitHub" on each page | `src/app/docs/[[...slug]]/page.tsx` | A 404 in the wrong repository |

The per-page link is assembled as:

```tsx
`https://github.com/${gitConfig.user}/${gitConfig.repo}/blob/${gitConfig.branch}/content/docs/${page.path}`
```

Note `content/docs/` is hardcoded there. If the content directory moves, that string moves with it.

To fix both, edit one file:

```ts title="src/lib/shared.ts"
export const appName = 'Langon Docs';

export const gitConfig = {
  user: 'langonrock',
  repo: 'docs',
  branch: 'main',
};
```

### The route constants

| Constant | Value | Used by |
| --- | --- | --- |
| `docsRoute` | `/docs` | `loader({ baseUrl })`, both rewrite patterns in `proxy.ts` |
| `docsImageRoute` | `/og/docs` | `getPageImageUrl()` |
| `docsContentRoute` | `/llms.mdx/docs` | `getPageMarkdownUrl()`, both rewrite patterns in `proxy.ts` |

Changing a constant updates the code that derives from it, **but not the App Router directory that
serves it** — those are file paths. Serving docs at `/guides` means editing `docsRoute` *and*
renaming `src/app/docs/` to `src/app/guides/`. Get one without the other and the proxy rewrites to a
route that does not exist.

## `next.config.mjs`

```js title="next.config.mjs"
import { createMDX } from 'fumadocs-mdx/next';

const withMDX = createMDX();

/** @type {import('next').NextConfig} */
const config = {
  reactStrictMode: true,
};

export default withMDX(config);
```

`createMDX()` is doing the heavy lifting. On first import it:

1. **Runs `init()` once per process** (guarded by an env flag) and emits `.source/`.
2. **Starts a file watcher** in development, so content edits regenerate the index.
3. **Registers three loaders** for both Turbopack and Webpack: the macro transform for files
   containing `'fumadocs-mdx/macro'`, the MDX compiler for `.md`/`.mdx`, and the meta loader for
   `.json`/`.yaml`.
4. **Sets `pageExtensions`** to `['mdx', 'md', 'jsx', 'js', 'tsx', 'ts']`.

Your own Next.js options go in `config`, and `withMDX()` merges them. Nothing else in the file needs
to change for ordinary configuration.

## `tsconfig.json`

Standard Next.js strict setup. The parts worth knowing:

| Setting | Why |
| --- | --- |
| `"strict": true` | Full strict mode |
| `"paths": { "@/*": ["./src/*"] }` | The `@/lib/source` style imports used everywhere |
| `"moduleResolution": "bundler"` | Required for the package `exports` maps that Fumadocs uses |
| `.next/types/**/*.ts` in `include` | Where `next typegen` writes `PageProps`, `LayoutProps`, `RouteContext` |

That last line is why `npm run types:check` runs `next typegen` before `tsc`.

## `eslint.config.mjs`

```js title="eslint.config.mjs"
const eslintConfig = defineConfig([
  ...nextVitals,
  globalIgnores(['.next/**', 'out/**', 'build/**', 'next-env.d.ts', '.source/**']),
]);
```

Flat config extending `eslint-config-next/core-web-vitals`. Add your own rules as further objects in
the array. `.source/**` must stay ignored — it is generated on every build.

## `postcss.config.mjs`

One plugin, `@tailwindcss/postcss`. See [Styling](/docs/development/styling) for how Tailwind is
configured — in CSS, not here.

## `.gitignore`

Generated output that should never be committed:

```
/node_modules
.source          # generated content index
/.next/          # build output
/out/ /build     # export output
next-env.d.ts    # generated types
.env*.local      # local secrets
.vercel          # Vercel link
```

Deleting `.source`, `.next`, and `next-env.d.ts` is always safe — they are recreated on the next
run.

## Environment variables

There are none. No `.env` file exists and nothing reads `process.env` outside of Next.js internals.
See [Environment, Secrets & TLS](/docs/operations/environment) for how to add them, where secrets
belong, and how API tokens are handled.

## Internationalization

Not configured, but the groundwork is visible: `page.locale` appears in `getPageImageUrl()` and
`getPageMarkdownUrl()`, and both `generateStaticParams()` implementations emit a `lang` key. All of
it is `undefined` today and filtered out, so it has no effect.

Enabling i18n means adding an `i18n` config to the `loader()` call in `src/lib/source.ts`, passing
it to `RootProvider`, and restructuring the routes under a `[lang]` segment. `createFromSource`
already detects `loader._i18n` and switches to per-locale search indexes on its own. Start from the
[Fumadocs i18n guide](https://fumadocs.dev/docs/ui/internationalization) rather than from the
leftovers here.
