The sidebar is generated from the folder structure of `content/docs/`. Without any configuration,
each folder becomes a collapsible group and its pages are sorted alphabetically by filename — which
is almost never the order you want to read them in.

A `meta.json` file inside a folder overrides that.

```json title="content/docs/writing/meta.json"
{
  "title": "Writing Content",
  "icon": "PenLine",
  "pages": ["mdx-basics", "frontmatter", "components", "navigation"]
}
```

## Ordering with `pages`

Entries are filenames without extensions, or subfolder names:

```json
{ "pages": ["index", "installation", "advanced-topics"] }
```

<Callout type="warn">
  `pages` is exclusive, not additive. A page you forget to list simply disappears from the sidebar —
  the page still builds and its URL still works, but nothing links to it. Add `"..."` if you want
  the leftovers included.
</Callout>

### Special entries

| Entry | Meaning |
| --- | --- |
| `"..."` | All remaining items, in default order |
| `"z...a"` | All remaining items, reversed |
| `"---"` | A plain horizontal separator |
| `"---Label---"` | A labelled separator |
| `"---[Rocket]Label---"` | A labelled separator with a Lucide icon |
| `"[Title](https://...)"` | An external link in the sidebar |
| `"[[Github]Title](https://...)"` | An external link with an icon |
| `"external:[Title](/path)"` | Force a link to be treated as external |
| `"!page-name"` | Exclude a page that `"..."` would otherwise include |
| `"...folder-name"` | Flatten a subfolder's children into this level |

A worked example:

```json title="content/docs/meta.json"
{
  "title": "Documentation",
  "pages": [
    "index",
    "---Guides---",
    "getting-started",
    "writing",
    "---[Wrench]Reference---",
    "development",
    "operations",
    "!internal-notes",
    "...",
    "[GitHub](https://github.com/langonrock/docs)"
  ]
}
```

## Folder icons

`icon` in `meta.json` sets the folder's icon; `icon` in a page's frontmatter sets that page's icon.
Both resolve through `lucideIconsPlugin()` and both take a PascalCase
[Lucide](https://lucide.dev/icons) name. An unknown name logs a warning and renders nothing.

## Sidebar tabs with `root`

Setting `"root": true` promotes a folder to a documentation root. Instead of nesting inside the
sidebar, it becomes a switchable tab, and its own tree replaces the sidebar contents when selected.

```json title="content/docs/api/meta.json"
{
  "title": "API Reference",
  "description": "Endpoint documentation",
  "icon": "Terminal",
  "root": true
}
```

Use this to separate genuinely distinct bodies of documentation — a guide and an API reference, or
docs for two different products. For ordinary grouping, a normal folder is the right tool.

## Collapse behavior

```json
{ "defaultOpen": true, "collapsible": false }
```

`defaultOpen` expands the folder on load. `collapsible: false` removes the toggle entirely, pinning
the folder open — reasonable for a short, important section, annoying for a long one.

## The page index

A folder's `index.mdx` becomes the page at the folder's own URL and heads its group in the sidebar.
To use a different file for that role without renaming it:

```json
{ "pagesIndex": "overview" }
```

## Current structure

For reference, this is how these docs are wired:

```json title="content/docs/meta.json"
{
  "title": "langondocs",
  "pages": ["index", "getting-started", "writing", "development", "operations"]
}
```

Each section folder then has its own `meta.json` with a `title`, an `icon`, and an explicit `pages`
array.
