Components come in two tiers, and the difference is invisible from inside an MDX file: some are
registered globally and some are not. Using an unregistered one without importing it produces a
build error rather than a warning.

## Registered globally

These need no import. They are provided by `defaultMdxComponents`, spread by `getMDXComponents()`
in `src/components/mdx.tsx`:

| Component | Purpose |
| --- | --- |
| `Card`, `Cards` | Linked cards in a responsive grid |
| `Callout` | Highlighted note, warning, or tip |
| `CalloutContainer`, `CalloutTitle`, `CalloutDescription` | Callout parts, for custom composition |
| `CodeBlockTabs` and family | Tabbed code blocks |

The same set also overrides plain HTML elements: `pre` becomes the Shiki code block, `a` becomes a
Next.js-aware link, `img` becomes a responsive image, `h1`–`h6` get anchors, and `table` gets a
horizontal scroll wrapper. That is why ordinary Markdown already looks right.

### Callout

```mdx
<Callout title="Heads up">This is worth knowing.</Callout>
<Callout type="warn">This runs against production.</Callout>
<Callout type="error">This deletes data.</Callout>
```

<Callout title="Heads up">This is worth knowing.</Callout>

<Callout type="warn">This runs against production.</Callout>

`type` accepts `info` (the default), `warn`, `warning`, `error`, `success`, and `idea`. An `icon`
prop overrides the icon that goes with the type.

### Cards

```mdx
<Cards>
  <Card title="Frontmatter" description="Every field." href="/docs/writing/frontmatter" />
  <Card title="Navigation" description="Sidebar order." href="/docs/writing/navigation" />
</Cards>
```

<Cards>
  <Card title="Frontmatter" description="Every field." href="/docs/writing/frontmatter" />
  <Card title="Navigation" description="Sidebar order." href="/docs/writing/navigation" />
</Cards>

`Card` takes `title` (required), `description`, `href`, `icon`, and `external`. Without `href` it
renders as a plain box instead of a link.

### Tabbed code blocks

````mdx
<CodeBlockTabs>
  <CodeBlockTabsList>
    <CodeBlockTabsTrigger value="npm">npm</CodeBlockTabsTrigger>
    <CodeBlockTabsTrigger value="pnpm">pnpm</CodeBlockTabsTrigger>
  </CodeBlockTabsList>
  <CodeBlockTab value="npm">
    ```bash
    npm install
    ```
  </CodeBlockTab>
  <CodeBlockTab value="pnpm">
    ```bash
    pnpm install
    ```
  </CodeBlockTab>
</CodeBlockTabs>
````

## Needs an import

Everything else lives in `fumadocs-ui/components/*` and must be imported at the top of the MDX file
that uses it:

```mdx
import { Steps, Step } from 'fumadocs-ui/components/steps';
```

| Import path | Exports | Purpose |
| --- | --- | --- |
| `fumadocs-ui/components/steps` | `Steps`, `Step` | Numbered sequences |
| `fumadocs-ui/components/tabs` | `Tabs`, `Tab` | Content tabs |
| `fumadocs-ui/components/accordion` | `Accordions`, `Accordion` | Collapsible sections |
| `fumadocs-ui/components/files` | `Files`, `Folder`, `File` | File tree diagrams |
| `fumadocs-ui/components/type-table` | `TypeTable` | Structured API/prop tables |
| `fumadocs-ui/components/banner` | `Banner` | Site-wide announcement bar |
| `fumadocs-ui/components/image-zoom` | `ImageZoom` | Click-to-zoom images |
| `fumadocs-ui/components/inline-toc` | `InlineTOC` | Table of contents in the body |
| `fumadocs-ui/components/github-info` | `GithubInfo` | Repository stars and forks |
| `fumadocs-ui/components/dynamic-codeblock` | `DynamicCodeBlock` | Runtime-highlighted code |

### Tabs

```mdx
import { Tab, Tabs } from 'fumadocs-ui/components/tabs';

<Tabs items={['macOS', 'Linux']}>
  <Tab value="macOS">Use Homebrew.</Tab>
  <Tab value="Linux">Use your package manager.</Tab>
</Tabs>
```

<Tabs items={['macOS', 'Linux']}>
  <Tab value="macOS">Use Homebrew.</Tab>
  <Tab value="Linux">Use your package manager.</Tab>
</Tabs>

The `items` prop is the shorthand form. `Tabs` also accepts the full composed API
(`TabsList`, `TabsTrigger`, `TabsContent`) when you need more control.

### Accordions

import { Accordion, Accordions } from 'fumadocs-ui/components/accordion';

</Accordions>

### File trees

```mdx
import { File, Folder, Files } from 'fumadocs-ui/components/files';

<Files>
  <Folder name="src" defaultOpen>
    <File name="index.ts" />
  </Folder>
</Files>
```

### Type tables

`TypeTable` takes a `type` object where each key is a field name:

```mdx
import { TypeTable } from 'fumadocs-ui/components/type-table';

<TypeTable
  type={{
    title: { type: 'string', required: true, description: 'The page title.' },
    full: { type: 'boolean', default: 'false', description: 'Render at full width.' },
  }}
/>
```

Each entry also accepts `typeDescription`, `typeDescriptionLink`, `deprecated`, `parameters`, and
`returns`. [Frontmatter](/docs/writing/frontmatter) uses it.

## Registering your own component

To make a component usable in every MDX file without an import, add it to `getMDXComponents`:

```tsx title="src/components/mdx.tsx"
import defaultMdxComponents from 'fumadocs-ui/mdx';
import type { MDXComponents } from 'mdx/types';
import { PricingTable } from './pricing-table';

export function getMDXComponents(components?: MDXComponents) {
  return {
    ...defaultMdxComponents,
    PricingTable,
    ...components,
  } satisfies MDXComponents;
}
```

`<PricingTable />` then works in any page. Note the spread order: `...components` comes last, so
the per-page overrides passed by the docs page — currently just `a` — always win.

<Callout>
  Prefer an import in the one file that needs it. Registering globally is for components used across
  many pages; each global registration is code shipped to every page whether it uses it or not.
</Callout>

## Client components

MDX pages are Server Components. A component that uses hooks, state, or browser APIs needs
`'use client'` at the top of its own file — not in the MDX. The Fumadocs components above already
handle this internally, which is why `Tabs` and `Accordions` work in a static page.
